# PhotoFindry 0.3.0-beta.9 · build 145

This Mac release makes failed photos easy to retry, keeps automatic background review out of your way, and stops cloud-drive remounts from growing the library catalog. Mac build 145 was published on 19 November 2026. Linux keeps 0.3.0-beta.8 / build 142 and Windows keeps 0.3.0-beta.2 / build 132; both stay on their own signed feeds. Build numbers 143 and 144 were used only for unpublished Windows test builds.

**Retry everything in Needs attention.** Choose the Needs attention filter and a new **Retry tagging for these photos…** action queues every photo whose tagging failed in the current source or folder, in one job, regardless of the page you are on or the search text. Photos whose earlier retag failed keep their current tags if the retry fails again. Photos listed only because an automatic improvement review failed keep their tags and are not retagged. Photos whose originals are offline wait in Jobs and continue by themselves when their folder returns, while the others are tagged.

**Automatic improvement stays quiet.** When the automatic "Improve saved photograph details" review cannot improve some photos, the batch no longer appears as a failed job in your queue and no longer adds a notification. The affected photos still show their issue in Needs attention, and the job stays in history with Retry available. Failed automatic batches left by earlier versions leave the queue after the update. If automatic review fails as a whole, for example because the review model keeps failing, it waits six hours before trying again instead of reloading the model for another batch. Improvement you start yourself is unaffected and reports failures as before.

**Cloud drives no longer grow the catalog.** Cloud drives such as pCloud present a new disk identity every time they reconnect. Earlier versions recorded a location-history entry for every photo on each reconnect even though nothing moved, which could grow a large library's catalog by hundreds of megabytes per reconnect and made Undo last source relocation point at a no-op. Reconnects now refresh location proof without adding history; real moves, renames and confirmations are still recorded and undoable.

**Clean up existing history and space.** In Files, a source with a large location history offers **Compact location history…**, which removes only those repeated reconnect entries in short, stoppable steps; moves, renames, confirmations and Undo are kept. When the catalog holds at least 64 MB of free space, **Reclaim … of catalog space…** rewrites it to return that space to the disk. Both ask for confirmation and change no originals, tags, names or previews.

Updates preserve the library, originals, model paths, saved lenses and saved work. All inference remains local. The MIT client excludes proprietary engine source and private development history. The beta 16 Mac-app migration channel is unchanged.

See QUALIFICATION.md for the exact candidate evidence and hardware limits. Public delivery is complete only after the delivered-byte, live-feed, installer, recovery and website checks pass.
